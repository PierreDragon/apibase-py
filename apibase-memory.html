The problem with AI agent memory today

Every session, your agent starts from zero. It doesn't remember the user's name, last week's findings, or the decision it made yesterday. The workarounds are painful — and none of them let you see what the agent actually knows.

🔒

Vector stores

Embeddings that no human can read. When the agent builds a wrong belief, you can't fix it because you can't see it.

📄

JSON files

Flat, no structure, no querying, no history. Fine for toy projects, painful at scale.

❌

Nothing

The most common solution. Every session is a blank slate. The agent never learns.

✅

APIBASE

Every memory is a row in a real table. A human can open it, read it, correct it, and understand it instantly.

The agent and the human work on the same data. That's the architecture — not an add-on.

Why AI agents love TLC addressing

APIBASE uses a deterministic address for every piece of data: T{table} / L{line} / C{column}. No ambiguity. No hallucination. An LLM can construct a valid query without guessing.

# Every cell in your base has an exact address
T30/L1/C2         # one cell: memorys, line 1, column "memory"
T30/L             # all records in memorys
T30/L/C2/O1?V=x   # records where memory = x

The address space is fully enumerable and self-consistent. This is why agents navigate it naturally — and why it works where other APIs fail.

HIVE — a fleet of agents with shared memory

APIBASE includes a HIVE system for multi-agent architectures. A boss agent owns the master base. Worker agents connect to it via a shared key and write their findings directly. The boss reads everything. The human sees everything.

Boss agent (full token)
    └── owns the master base
    └── controls who can read, write, edit
 
Worker "research" (hive token — read + add)
    └── writes findings into boss memory
    └── cannot edit or delete what boss wrote
 
Worker "analyst" (hive token — read only)
    └── reads directives from boss
    └── cannot write
from apibase import ApibaseClient, HiveClient, Memory

# Boss reads and writes its own base
boss = ApibaseClient("https://apibase.work", full_token)
mem  = Memory(boss, table_id=30, agent_col="username", agent="boss")

# Worker writes into boss base via HIVE
worker  = HiveClient("https://apibase.work", hive_token)
mem_w   = Memory(worker, table_id=30, basekey="claude", agent="research")

mem_w.remember("finding01", "Revenue spike detected on 2026-04-15")
mem.search("spike")  # boss finds it immediately

Every write is visible in real time through the APIBASE interface. You know which agent wrote what, when, and why.

API reference

Memory methods

MethodDescription
remember(key, value)Store or update a memory
recall(key)Retrieve a value by key
forget(key)Delete a memory
search(text)Search across keys and values
all()All memories (filtered by agent if set)

HIVE workflow

MethodDescription
request(basekey, table_id)Request access to a table
approve(basekey, id_hive)Approve a pending request
publish(basekey, id_hive)Push a data snapshot to the requester

Naming conventions

APIBASE enforces strict naming. Memory keys must follow the same rules — no underscores (reserved for id_x and x_id). Use username not user_name, dot notation for composed meaning: created.at.

apibase-py is built on APIBASE — structured data platform, file-based, no database server required.
